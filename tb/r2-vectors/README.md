# R2 read vectors - $readmemh export

Generated by `python3 -m tools.host_gui.r2_vectors --hex` from the same
build as `../R2-READ-VERIFICATION.json`; `--check` proves every file

here is byte-identical to the JSON frame AND to the shipped model
image, so a testbench can consume these files directly and there is
no translation step.

**Status: NOT chip-confirmed** - CHIP-CONFIRMED IN SIMULATION: all 22 golden steps in this package pass byte-exactly (CRC included) in the chip repo's tb/tb_pe_ctrl_r2.v, with the model image loaded per vector; see the chip repo's reviews/2026-09-25/R2-READ-PATH-REVIEW.md, section 'Conformance', which names every step (22/22). NOT HARDWARE-CONFIRMED: the real-board acceptance run (Pico over USB CDC with a physical shuttle) has NOT been executed and is not claimed here. The host probes in r2_reads.py still run against the FakePE model; what the chip confirms is that the RTL matches these same expectations.

## Load procedure (Verilog)

```verilog
// 1. the model image: 1024 IMEM words, 16 DMEM bytes
initial begin
  $readmemh("imem.hex", imem);   // logic [15:0] imem [0:1023]
  $readmemh("dmem.hex", dmem);   // logic [7:0]  dmem [0:15]
end
// 2. preload the registers for the vector under test from
//    model_images[].state in manifest.json:
//      pc (10b), a/x/y (8b), insn (16b), timer, run, faults,
//      words_written
// 3. drive the step's request_file and compare against response_file
```

`imem.hex` is one 16-bit word per line in ascending address order;
`dmem.hex` is one byte per line. The per-step request/response files
are one byte per line in wire order.
