# .known-rule-violations.txt — the PINNED BASELINE for check_wiki_pages.sh
#
# WHY THIS FILE EXISTS. wiki/SCHEMA.md states five rules for hand-written pages
# (frontmatter present, `type` inside the enum, every tag inside the taxonomy,
# at least two outbound wikilinks, listed in index.md). Until 2026-09-25
# NOTHING checked any of them: every documentation gate in regress/run_all.sh
# was a GENERATED-page drift check, comparing wiki/reference/* against
# tools/gen/*. So a hand-written page could violate all five with no gate
# noticing. This file is how the gate could be landed at all.
#
# THE SHAPE, and why it is this shape rather than "fix the pages first".
# A gate written today would be RED on 12 violations across 8 pages. Landing a
# red gate on another worker's suite is not a call a docs task makes, and
# deleting a rule because the wiki currently breaks it is the wrong cure - the
# rules are right, the corpus is not. So the violations are PINNED, exactly
# the way tb/r3-vectors/R3_KNOWN_DIVERGENCES.txt pins a known divergence set,
# and the checker enforces the pin in BOTH directions:
#
#   * a violation NOT listed here            -> NEW    -> RED
#   * a listed entry that NO LONGER FAILS   -> STALE  -> RED
#
# The second half is the half that matters. Without it this file is a ratchet
# that silently becomes wrong: somebody fixes a page, the entry stays, and the
# gate still reports the violation it no longer sees - so the log and the tree
# disagree and nobody can tell which one is true. A baseline that cannot go
# stale is a checklist; this one has to be able to fail.
#
# FORMAT: `<page-relative-to-wiki/> <rule> <reason...>`. Fields 1 and 2 are
# machine-read; the reason is free text and is never parsed. A blank line or a
# line starting `#` is a comment. A MALFORMED line is an error, not a skip -
# fail-closed, because a baseline entry this checker cannot read is an entry
# that silently stops being enforced.
#
# MEASURED 2026-09-25 over 43 hand-written pages. The other rule violations
# found that day - 23 off-taxonomy tags across 9 pages - were NOT pinned: the
# manager ruled they were a defect in the taxonomy, and wiki/SCHEMA.md now
# carries all 23. That is why the taxonomy extension and this file are one
# change: the rules are enforced, and the thing that was actually wrong got
# fixed rather than excused.
#
# TO CLOSE AN ENTRY: fix the page, then DELETE the line. The checker will
# refuse to pass with a stale entry, so this is not optional bookkeeping.
#
# ---------------------------------------------------------------------------
# STATUS 2026-09-26: NO PINNED VIOLATIONS REMAIN. This file is now EMPTY of
# entries, and both rules it was pinning are CLEAN across all 43 hand-written
# pages:
#
#   no-frontmatter     0 of 43   was 4  (3 plans/ + 1 reference/)
#   zero-outbound-links 0 of 43  was 8  (7 plans/ + 1 reference/)
#
# THE HEADER IS KEPT DELIBERATELY, not because there is anything left to pin but
# because the mechanism has to be able to come BACK. Both directions are still
# enforced: a new violation is NEW and red, and re-adding a line here for a
# violation that no longer fails is STALE and red. An empty baseline that is
# deleted cannot record that this corpus was once 12 red, and the next person to
# break a rule would have no idea a file like this exists.
#
# IF YOU HAVE TO PIN SOMETHING AGAIN: fix the page first. A pin is a record that
# a rule is currently not met, and the whole value of this file was that every
# line in it was true. See regress/check_wiki_pages.sh for the rules themselves.
