# R3 debug vectors - $readmemh export

Generated by `python3 -m tools.host_gui.r3_vectors --hex` from the same
build as `../R3-DEBUG-VERIFICATION.json`; `--check` proves every file

here is byte-identical to the JSON frame AND to the shipped model
image, so a testbench can consume these files directly and there is
no translation step.

**Status: NOT chip-confirmed** - NOT CHIP-CONFIRMED. Reconciled against the implemented R3 contract (chip repo, 2026-09-25), but no step here has been run against the chip's tb_pe_ctrl_r3 yet, so every step is chip_confirmed=false. A passing step in this package is the gate the chip must meet, NOT evidence that it does. The real-board acceptance run has not been executed.

## Load procedure (Verilog)

```verilog
// 1. the model image: 1024 IMEM words, 16 DMEM bytes
initial begin
  $readmemh("imem.hex", imem);   // logic [15:0] imem [0:1023]
  $readmemh("dmem.hex", dmem);   // logic [7:0]  dmem [0:15]
end
// 2. preload the registers for the vector under test from
//    model_images[].state in manifest.json:
//      pc (10b), a/x/y (8b), insn (16b), timer, run, faults,
//      words_written
// 3. drive the step's request_file and compare against response_file
//    and model_images[].debug: bp_addr, bp_en, bp_hit,
//    debug_hold (the state word is DERIVED from these)
```

`imem.hex` is one 16-bit word per line in ascending address order;
`dmem.hex` is one byte per line. The per-step request/response files
are one byte per line in wire order.
